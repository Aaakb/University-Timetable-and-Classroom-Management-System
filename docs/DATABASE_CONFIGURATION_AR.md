# إعداد اتصال قاعدة البيانات للنسخة المثبتة

عدّل `database-settings.json` بجانب ملف تشغيل البرنامج، داخل مجلد التنصيب، ثم أعد تشغيل البرنامج. لا تحتاج إعادة بناء التطبيق لتغيير السيرفر أو اسم القاعدة. ملف المصدر موجود داخل مشروع Presentation Layer في `University Timetable and Classroom Management System/database-settings.json`، ويُنسخ تلقائيًا إلى مخرجات البناء والنشر، ويظل ملفًا خارجيًا عند النشر كملف تنفيذي واحد.

توجد نسخة مصدر واحدة في Presentation Layer. يشير مشروع DAL إليها كملف مرتبط للنسخ عند البناء والنشر، كي تحصل API والأدوات والاختبارات التي تعتمد عليه على الإعداد نفسه؛ هذا ارتباط بملف محتوى، وليس ProjectReference عكسيًا إلى مشروع الواجهة. لم يتغير كود قراءة الاتصال أو أولوية متغير البيئة.

```json
{
  "ConnectionStrings": {
    "UniversityTimetable": "Server=.\\SQLEXPRESS;Database=UniversityTimetable;Trusted_Connection=True;Encrypt=False;TrustServerCertificate=True;"
  }
}
```

استبدل `.\\SQLEXPRESS` باسم SQL Server المناسب، و`UniversityTimetable` باسم قاعدة البيانات. الشرطة العكسية داخل JSON تكتب مرتين: `SERVER\\INSTANCE`. القيم الافتراضية أعلاه مطابقة للقيم السابقة في الكود.

الأولوية تبقى لمتغير البيئة `UNIVERSITY_TIMETABLE_CONNECTION_STRING` إن كان موجودًا؛ تستخدمه الاختبارات والأدوات. في API يبقى إعداد `ConnectionStrings:UniversityTimetable` الخاص بالمضيف، إن ضُبط عبر إعداداته أو user-secrets أو البيئة، أعلى أولوية كما كان؛ وعند غيابه يُقرأ ملف `database-settings.json` المشترك.

القراءة تعتمد على مجلد التطبيق، وليس مجلد العمل الحالي. الملف مطلوب عند غياب override؛ غيابه أو JSON غير صالح أو قيمة اتصال فارغة ينتج خطأ بدل الاتصال الصامت بقاعدة أخرى.

عند تجهيز المثبّت، ضمّن الملف بجانب executable، وحدد له سياسة الحفاظ على إعداد العميل عند ترقية النسخة. إعدادات النسخ في المشروع تضمن تضمين الملف في build/publish، لكنها لا تفرض سياسة الاستبدال على برنامج التنصيب. لا توجد ملفات مشروع مثبّت في المصدر المفحوص.

هذا التغيير يخص اختيار الاتصال فقط؛ لا ينشئ أو يطبّق migrations ولا يعدّل schema. تشغيل التطبيق نفسه يحتفظ بسلوك الصيانة الموجود سابقًا.

## التحقق المنفذ

- نجح بناء الحل كاملًا: صفر أخطاء وصفر تحذيرات.
- نجحت 12 حالة في `tests/DatabaseConfiguration`: القيم الافتراضية، تعديل الملف وإعادة قراءته، استخدام مجلد التطبيق، أولوية البيئة عند تلف الملف أو غيابه، ورفض الملف المفقود والإعدادات الفارغة أو غير الصالحة.
- نجحت الفحوص الـ51 في `tests/PresentationBllRefactoring` دون فشل.
- نجح نشر سطح المكتب وAPI محليًا بإعداد Debug، وتطابقت بصمة ملف JSON المنشور مع المصدر. هذه مخرجات تحقق للنشر، وليست نسخة تنصيب Release مُجهزة للتوزيع. إعداد `ExcludeFromSingleFile` موجود؛ لم يُنفذ نشر single-file في هذا التحقق.
- لم يُفتح اتصال SQL، ولم تُختبر CRUD أو المعاملات وقت التشغيل؛ لا ادعاء بتحقق تكاملي كامل.

إعادة تشغيل فحوص الاتصال دون قاعدة بيانات:

```powershell
dotnet run --project tests/DatabaseConfiguration/DatabaseConfiguration.csproj
```

يغيّر الفحص نسخته الخاصة في مجلد مخرجات الاختبار ثم يعيدها، ولا يعدّل إعدادات المصدر أو النسخة المثبتة.
