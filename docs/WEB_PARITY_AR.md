# وظائف نسخة الويب والتحقق منها

## الوظائف الحالية
- إدارة المواد والتدريسيين والقاعات والفروع والمراحل والشعب والتكليفات والفترات والجداول.
- عرض الجدول الأسبوعي، ترشيح الفصل، التثبيت، توليد الجدول، وتصدير PDF والطباعة.
- استيراد أسماء التدريسيين والمواد من Excel بصيغة xlsx فقط، مع ربط الأعمدة ومعاينة وحفظ مؤكد. لا تقبل واجهة الويب استيراد PDF أو أوضاع Timetable/Hybrid/Repair. تصدير PDF متاح.
- حفظ نسخة الجدول JSON واستعادتها مع معاينة ونسخة أمان، وتفضيلات الأيام والفترات ومقارنة الجداول البديلة.
- التسجيل وإجراءات الكتابة للمسؤول فقط؛ [تفاصيل الصلاحيات](WEB_AUTHORIZATION_AR.md).

الحد الأقصى للملف 20 MB، ولـExcel بعد فك الضغط 100 MB، و100 ورقة و500 ألف خلية. واجهة الاستيراد تعرض 50 صفاً في الصفحة دون إسقاط بقية الصفوف.

## الاختبارات الحالية
نفّذ من جذر المشروع:

```powershell
dotnet run --project tests/WebActualApi
dotnet run --project tests/WebDataTransfer
dotnet run --project tests/WebParity
node tests/WebParity/navigation.mjs
node tests/WebParity/run-browser.mjs
```

WebActualApi يختبر API حقيقية ومتصفح Edge: الصلاحيات، البحث وتقسيم الصفحات، تعديل المواد، الاستيراد الأكاديمي، وإضافة/تعديل/حذف الفروع وعرض الفصلين. WebDataTransfer يختبر الاستعادة ونسخة الأمان والتفضيلات والاستيراد المؤكد ورفض الأنواع والأوضاع غير المدعومة. كلاهما يستخدم قاعدة مؤقتة مستقلة ويزيلها عند الانتهاء. اختبارات المتصفح الأخرى تستخدم API محاكاة لاختبار فشل التحميل وانتهاء الجلسة والحفظ السريع أثناء انتقال الصفحة. تحتاج SQL مع إذن إنشاء وحذف قاعدة الاختبار، وNode وPlaywright وEdge.

اختبار WebIntegration القديم يخص عقداً سابقاً ويستخدم القاعدة المضبوطة مباشرة؛ لا يُستخدم لاعتماد هذا الإصدار. الاختبارات المعتمدة أعلاه تعمل بقواعد مستقلة ولا تتطلب فتح التسجيل العام.

## الأداء والتزامن
البحث وتقسيم صفحات الموارد ينفذان في SQL بترتيب ثابت. القوائم الأساسية تجلب 25 سجلاً لصفحة العرض، مع بحث مؤجل 200ms. شاشات الهيكل الأكاديمي والجدول الأسبوعي تحمل البيانات اللازمة لمرشحاتها المترابطة وعرض الأسبوع؛ صفحات SQL لا تعيد تحميل كامل الجدول قبل Skip/Take. لا يمثل ذلك اختبار حمل أو ضماناً لسعة مستخدمين معينة.

قفل الكتابة داخل عملية الويب لا ينسق تغييرات تطبيق سطح المكتب؛ يلزم تحديث البيانات عند التعديل من الواجهتين. حالة المعاينات في الذاكرة، ولذلك التشغيل الحالي بعملية واحدة. الواجهة PWA تحتاج خادم التطبيق وقاعدة البيانات لإجراءات البيانات حتى عند تثبيتها.
