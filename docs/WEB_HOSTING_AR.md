# نشر النظام الكامل وإصلاح موقع Netlify

الموقع الحالي ينشر واجهة ثابتة بملف `api.js` بديل يستعمل `localStorage`. هذا لا يقرأ قاعدة SQL Server، ولا يطبّق خدمات التوليد والاستيراد الأصلية. نسخة المشروع المحلية تحتوي ملف الاتصال الحقيقي؛ لا تستبدله بمحاكاة محلية.

## المسار المتوافق مع وظائف المشروع الحالية

انشر تطبيق ASP.NET Core والواجهة معًا على Windows / IIS يدعم .NET 8 وعمليات البحث الطويلة، مع قاعدة SQL Server يستطيع الخادم الوصول إليها. هذا يحافظ على طلبات `/api` والجلسات في العنوان نفسه.

على الخادم يجب تثبيت ASP.NET Core Hosting Bundle الموافق لـ.NET 8 وإعداد موقع IIS بشهادة HTTPS. ارفع **محتويات** ملف `ASP.NET-Server.zip` إلى مجلد الموقع، بما فيها `web.config` و`wwwroot` وملفات المكتبات الأصلية. لا ترفع حزمة الخادم إلى Netlify؛ هي مخصصة لاستضافة ASP.NET Core. [تعليمات Microsoft](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/iis/?view=aspnetcore-8.0)

## تجهيز الملفات

من جذر المشروع:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Publish-WebHosting.ps1
```

يُنشئ الأمر مجلدًا جديدًا داخل `output` يحتوي الحزمة ودليل النشر. لا يغير قاعدة الجامعة ولا إعدادات التشغيل المحلية. الحزمة تعتمد تثبيت .NET 8 على الخادم، وتستهدف Windows x64. حُذفت إعدادات اتصال جهاز المطور من **الحزمة فقط**؛ لن تبدأ الحزمة حتى يُضبط اتصال الخادم.

إذا عرفت عنوان الاستضافة الحقيقي، مرّره كذلك:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Publish-WebHosting.ps1 -PublicUrl https://YOUR-DOTNET-HOST.example
```

استبدل العنوان بعنوان ASP.NET الفعلي. يضبط الأمر `AllowedHosts` داخل الحزمة ويضيف `Netlify-Redirect.zip`. عند غياب العنوان، عدّل `AllowedHosts` في `appsettings.Production.json` المنشور إلى اسم نطاق الاستضافة الفعلي قبل التشغيل.

## قاعدة البيانات

رفع الموقع لا ينقل بيانات SQL تلقائيًا. استعد نسخة SQL Server كاملة من قاعدة `UniversityTimetable` على خادم قاعدة البيانات، أو هيئ وصولًا خاصًا من خادم التطبيق إلى قاعدة الجامعة القائمة. **ملف «نسخة الجدول» JSON ليس نسخة لقاعدة البيانات كاملة** ولا يكفي لنقل المواد والتدريسيين والحسابات والموارد.

اضبط متغير البيئة التالي في إعدادات تطبيق ASP.NET على الخادم:

```text
ConnectionStrings__UniversityTimetable
```

قيمته سلسلة الاتصال التي توفرها استضافة SQL Server، مع اسم الخادم والقاعدة والحساب المناسب. يمكن بدلًا منه ضبط `UNIVERSITY_TIMETABLE_CONNECTION_STRING` عند عدم وجود إعداد الاتصال الأعلى أولوية. لا تضع بيانات SQL في JavaScript أو ملفات Netlify. الإعداد `Integrated Security=True` المحلي يعتمد هوية Windows ولن يمنح الخادم المستضاف صلاحيات حسابك على جهازك.

للتعديل عبر ملف، يمكن ضبط `database-settings.json` على الخادم داخل مجلد التطبيق، خارج `wwwroot`، مع حمايته من القراءة العامة. تظل متغيرات إعداد الاتصال أعلى أولوية منه.

تحقق من أن هوية تشغيل IIS تستطيع قراءة ملفات التطبيق وكتابة نسخ الأمان ومفاتيح جلسات ASP.NET في موقع دائم. أبقِ التطبيق في عملية واحدة لأن المعاينات وقفل عمليات الويب محفوظان في ذاكرة العملية. لا تُفعّل عدة نسخ خلف موزع حمل دون نقل هذه الحالة إلى تخزين مشترك.

## ماذا أفعل برابط Netlify الحالي؟

بعد تشغيل الموقع الكامل، يمكن رفع **Netlify-Redirect.zip فقط** إلى موقع Netlify الحالي. يحوّل المتصفح إلى عنوان التطبيق الكامل، وبعدها تجري طلبات البيانات مباشرة على خادم ASP.NET. التحويل مؤقت `302` لتسهيل تغييره عند الحاجة، ولا ينقل قاعدة البيانات.

يوجد خيار إبقاء الواجهة على Netlify وتمرير `/api` عبر proxy، لكن Netlify يقطع طلبات الـproxy بعد 26 ثانية، بينما بعض عمليات تحسين الجدول تصل إلى 120 ثانية. لذلك التحويل إلى الموقع الكامل يحافظ على المسارات الحالية دون قطع هذه العمليات. إبقاء عنوان Netlify أثناء عمليات البحث الطويلة يحتاج تحويلها إلى مهام خلفية تُتابع بطلبات قصيرة. [توثيق Netlify وحدود الـproxy](https://docs.netlify.com/manage/routing/redirects/rewrites-proxies/)

## التحقق بعد النشر

1. افتح `https://YOUR-DOTNET-HOST.example/api/auth/csrf`: يجب أن تحصل على JSON يتضمن `token`، وليس صفحة HTML أو 404.
2. افتح `/api/auth/me` دون تسجيل دخول: المتوقع `401`، وهو دليل وصول الطلب إلى ASP.NET.
3. سجل الدخول بحساب من قاعدة البيانات المنقولة، وتحقق من عدد المواد والتدريسيين ومحاضرات الفصلين.
4. جرّب تنزيل نسخة جدول وملف PDF، ثم معاينة ملف استيراد دون حفظ.
5. جرّب عمليات التوليد والاستعادة على بيئة اختبار قبل استخدامها مع جدول الجامعة.

إنشاء الحسابات في الويب يتطلب مسؤولاً مسجلاً. صلاحيات الإدارة تُحدد بواسطة `Authorization:AdministratorIds`، وبقية الحسابات للقراءة فقط. راجع [إعداد الصلاحيات](WEB_AUTHORIZATION_AR.md) لتحديد معرفات مسؤولي هذا الخادم.
