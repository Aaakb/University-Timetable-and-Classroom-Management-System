# University Timetable Management System — تشغيل الويب

## التشغيل على الكمبيوتر نفسه

الطريقة الأسهل: انقر مرتين على `Start-Web.cmd` الموجود في مجلد المشروع الرئيسي.
يحدد هذا الملف مسار المشروع تلقائيًا، حتى عند تشغيله من مجلد آخر. اترك نافذته مفتوحة.
إذا ظهر `The provided file path does not exist: UniversityTimetable.API`، فإن المسار
النسبي لا يُحلّ من المجلد الحالي؛ استخدم ملف التشغيل أو المسار الكامل لملف `.csproj`.

من PowerShell داخل مجلد المشروع:

```powershell
dotnet run --project UniversityTimetable.API --launch-profile local
```

ثم افتح **http://localhost:5180** في Edge أو Chrome.
يمكن أيضًا تشغيل `Start-Web.ps1` من مجلد المشروع. أوقف الخادم باستخدام Ctrl+C.
تبقى خدمة SQL Server والخادم مطلوبتين حتى بعد تثبيت التطبيق.

استخدم حساب Windows Forms نفسه، أو أنشئ حسابًا من شاشة الدخول.
الحسابات الحالية لا تحتوي على أدوار مختلفة؛ كل حساب مسجل يملك صلاحيات الإدارة
الموجودة في التطبيق الأصلي. لم تُضف صلاحيات وهمية أو حسابات افتراضية.

للبناء فقط:

```powershell
dotnet build "University Timetable Management System.slnx"
```

المتطلبات: Windows، و.NET SDK قادر على بناء net8.0، وASP.NET Core Runtime 8،
وقاعدة SQL Server الأصلية. الإصدارات المثبتة في بيئة التطوير اجتازت البناء.

## قاعدة البيانات

يستخدم الويب وWindows Forms `DatabaseConnection` نفسه. الإعداد الافتراضي الموجود
في التطبيق الأصلي هو SQL Express المحلي وقاعدة `UniversityTimetable` مع مصادقة Windows.
لم تُنشأ قاعدة إضافية ولم تُنفذ migrations أو seeding أو صيانة تلقائية.

لتحديد اتصال مختلف لنفس القاعدة القائمة، عيّن متغير البيئة التالي في جلسة التشغيل:

```powershell
$env:UNIVERSITY_TIMETABLE_CONNECTION_STRING = 'Server=YOUR_SQL_INSTANCE;Database=UniversityTimetable;Integrated Security=True;Encrypt=True;TrustServerCertificate=False'
dotnet run --project UniversityTimetable.API --launch-profile local
```

استبدل اسم الخادم بما يطابق تثبيتك. يحتاج Encrypt=True إلى شهادة SQL موثوقة.
لا تنسخ هذا المثال حرفيًا إذا كان تثبيتك يستخدم إعدادات محلية مختلفة.
يدعم الويب أيضًا `ConnectionStrings__UniversityTimetable` أو user-secrets بالمفتاح
`ConnectionStrings:UniversityTimetable`. هذا الإعداد يأخذ أولوية داخل عملية الويب فقط؛
تأكد من أنه يشير إلى قاعدة سطح المكتب نفسها. لا تحفظ كلمات مرور داخل الملفات المتتبعة.

## التثبيت وHTTPS

في Edge/Chrome العادي، افتح التطبيق ثم استخدم زر «تثبيت التطبيق» عند ظهوره، أو
خيار تثبيت التطبيق من قائمة المتصفح. قد لا يظهر هذا الخيار في التصفح الخاص.
تُعامل localhost كسياق آمن لأغراض Service Worker؛ فحص Chromium لقابلية التثبيت نجح.
لم يُنفّذ تثبيت دائم على نظام المستخدم أثناء الاختبار.

لتشغيل HTTPS محليًا:

```powershell
dotnet dev-certs https --trust
dotnet run --project UniversityTimetable.API --launch-profile https
```

ثم افتح https://localhost:7180. أمر الثقة قد يعرض نافذة تأكيد من Windows.
لم تُغيّر شهادات الجهاز أو قواعد الجدار الناري أثناء التنفيذ.

عنوان localhost على الهاتف يشير إلى الهاتف نفسه. للوصول من الشبكة لاحقًا، يلزم
عنوان الخادم المناسب، binding للشبكة، AllowedHosts مطابق، HTTPS بشهادة يثق بها
الهاتف، وقاعدة جدار ناري محدودة. لا تفتح منفذ SQL Server للعامة. الإعداد الحالي
يربط الخادم بـlocalhost فقط، ويرفض طلبات API غير المشفرة الواردة من أجهزة أخرى.

## الاستخدام

- صفحات القاعات والفروع والمراحل والشعب والمواد والتدريسيين والتكليفات والأوقات تدعم الإضافة والتعديل والحذف.
- سجل المادة يرتبط بالمرحلة والفرع والفصل والساعات ونوع المتطلب.
- تعرض نافذة المحاضرة التدريسيين المكلفين بالمادة والشعب المطابقة، وتطبق الخادم قواعد النظام الأصلية.
- الجدول يدعم البحث والتصفية بالفصل والمرحلة والفرع والشعبة والتدريسي والقاعة واليوم والنوع والمجموعة.
- تصفية المجموعة تشمل محاضراتها العملية والمحاضرات النظرية المشتركة مع شعبتها.
- تصدير PDF يعيد استخدام محرك التصدير الأصلي. الطباعة تفتح نافذة طباعة المتصفح.
- «توليد الجدول» يستبدل الجدول الحالي عند النجاح الكامل فقط، بعد تأكيد صريح ومراجعة إصدار بياناته.
- تحديث البيانات يعرض تغييرات قاعدة البيانات من أي من التطبيقين؛ لا توجد مزامنة لحظية عبر SignalR.

## البيانات دون اتصال والتحديثات

يخزّن Service Worker ملفات الواجهة والأيقونات فقط. لا يخزن ردود API أو الحسابات
أو الجداول في Cache Storage أو localStorage. عند غياب الخادم تظهر صفحة عدم اتصال،
ولا تُرسل عمليات حفظ لاحقًا بشكل خفي ولا تُعرض نجاحات وهمية.

عند إصدار ملفات واجهة جديدة، غيّر اسم CACHE في `wwwroot/service-worker.js`.
يظهر إشعار تحديث للمستخدم، ولا يُفرض تحديث أثناء عملية حفظ أو توليد. عند الخروج
تُمسح البيانات المعروضة من الذاكرة والواجهة وتُنهى جلسة المتصفح.

## حدود مهمة

فحص نسخة السجل يمنع الحفظ من شاشة قديمة، وعمليات الويب تُسلسل داخل الخادم.
لكن طبقة البيانات الأصلية لا توفر فحص نسخة ذريًا مشتركًا بين العمليتين؛ لذلك
تجنب تعديل السجل نفسه أو تشغيل التوليد من Windows Forms والويب في الوقت نفسه.
ضمان ذلك تمامًا يحتاج تعديلًا مشتركًا في BLL/DAL وربما rowversion في قاعدة البيانات.

قاعدة البيانات الحالية تفرض أنواع المتطلبات University / College / Department.
خيارات المصمم القديم مختلفة، ولذلك استخدمت الواجهة الجديدة القيم المقبولة فعليًا،
مع إبقاء سطح المكتب دون تعديل. كذلك تفرض قاعدة البيانات عدد طلبة أكبر من صفر.

قبل النشر العام يلزم مراجعة سياسة التسجيل وكلمات المرور القديمة (الحد الأدنى
الحالي 4 أحرف) والتزامن وشهادات HTTPS وإدارة أسرار الخادم. لم يتم نشر التطبيق على الإنترنت.

## التحقق وإعادة الاختبار

ابدأ الخادم ثم شغّل:

```powershell
dotnet run --project tests/WebIntegration
```

هذا الاختبار ينشئ سجلات مؤقتة مميزة في القاعدة نفسها، وينظف السجلات الخاصة به فقط،
ويقارن بصمات جميع السجلات قبل الاختبار وبعده. لا يستبدل الجدول ولا ينشئ قاعدة ثانية.
شغّله في وقت لا يوجد فيه مستخدم آخر يعدّل البيانات حتى تكون المقارنة ذات معنى.
ملفات النتائج تقع في `.tmp/WebIntegration` ولا تحتوي كلمات المرور المؤقتة.

لاختبار المتصفح أيضًا، يجب توفر Node وPlaywright وEdge. اضبط `PLAYWRIGHT_MODULE`
على المسار الكامل لملف `playwright/index.mjs` في تثبيتك إذا لم يكن بجوار Node:

```powershell
dotnet run --project tests/WebIntegration -- --browser
```

يستخدم الاختبار ملف متصفح مؤقتًا، ويمرر بيانات الحساب المؤقت في ذاكرة العملية،
ويزيل ملف المتصفح بعد الانتهاء. تم اختبار الشاشات من 360×800 إلى 1920×1080.

لاختبار التخطيط على البيانات الحالية **دون أي حفظ أو استبدال للجدول**:

```powershell
dotnet run --project tests/WebIntegration -- --plan-current
```

تأكد من تطابق إعداد اتصال عملية الاختبار مع اتصال خادم الويب. إذا غيّرت الكود،
أوقف الخادم قبل إعادة البناء لتجنب قفل الملف التنفيذي في Windows، ثم أعد تشغيله.

## استكشاف الأعطال

- خطأ الاتصال: تحقق من خدمة SQL Server واسم instance والقاعدة وصلاحيات حساب Windows.
- المنفذ مستخدم: أغلق نسخة الخادم السابقة، أو استخدم `--no-launch-profile --urls http://localhost:5181`.
- رسالة تغيّر السجل: حدّث البيانات ثم افتح السجل مجددًا؛ لا تُستبدل تعديلات مستخدم آخر تلقائيًا.
- رفض الحذف: قد توجد محاضرات أو علاقات أخرى تعتمد على السجل.
- عدم ظهور التثبيت: استخدم متصفحًا داعمًا خارج التصفح الخاص، وتحقق من localhost أو HTTPS والأيقونات.
- لتشخيص أخطاء الخادم، طابق رقم التتبع مع سجل نافذة التشغيل. لا تُطبع تفاصيل SQL أو كلمات المرور في رسائل الواجهة.
