# محرر أيام التدريسي باستخدام CP-SAT

هذه الوثيقة تخص محرر الأيام السابق `FacultyScheduleEditorForm` وخدمات التوافق القائمة. الزر الحالي في القائمة يفتح شاشة [تفضيلات التدريسيين](FacultyPreferences.md) ذات الدرجات الثلاث وخطة حضور يومين أو ثلاثة. لا يُسمح باستخدام المحرر السابق لتجاوز مصفوفة تفضيلات جديدة محفوظة.

## الاستخدام

1. اختر التدريسي (تدعم القائمة البحث بالاسم العربي أو الإنجليزي) والفصل الدراسي.
2. راجع تبويب **الجدول الحالي**.
3. اختر أيام التدريس، وحدد النمط صراحةً: **صارم** أو **تفضيل**. يمكن تحديد أيام غير متاحة وفترات مفضلة ومهلة بحث.
4. **فحص الفترات المتاحة** يعرض تركيبات اليوم والفترة والقاعة الممكنة لكل محاضرة منفردة؛ لا يُعد ذلك إثباتًا لوجود توزيع كامل.
5. اضغط **إنشاء المقترح**؛ راجع أعمدة الموعد والقاعة قبل وبعد، والمحاضرات التي تغيرت، وأي محاضرة خارج الأيام المفضلة. لا تُكتب المعاينة إلى القاعدة.
6. اضغط **حفظ التغييرات** ووافق على التأكيد الصريح. الإلغاء أو إغلاق النافذة دون حفظ يترك الجدول كما هو. تغيير الخيارات يُبطل المقترح.

## القيود والحفاظ على الجدول

- النطاق هو محاضرات التدريسي المختار في الفصل المختار فقط. تبقى محاضرات بقية التدريسيين والفصل الآخر دون تغيير.
- تبقى معرّفات المحاضرات وموادها ومدرّسوها وشعبها وفروعها ومجموعاتها وأنواعها ومددها كما هي. لا يُحذف طلب محاضرة ولا تُنشأ محاضرة إضافية.
- المتغيرات المسموحة: اليوم، والفترة ذات المدة المطابقة، والقاعة الملائمة.
- تستخدم الخيارات قواعد الأيام الحالية `ScheduleDayRules.AllDays`، والفترات والقاعات والسعات والعلاقات من قاعدة البيانات. الواجهة لا تنشئ قائمة مستقلة لأيام التدريس. أيام التدريس الحالية مصدرها الكود، وليس جدول إعدادات في القاعدة.
- فحص الخيارات يستخدم `ScheduleRoomSelector` و`ScheduleConflictChecker` الحاليين. يعاد التحقق عبر `ScheduleService.ValidateAsync` وفحص تعارضات الجدول الكامل قبل الحفظ.
- محاضرات الآخرين قيود ثابتة في الذاكرة فقط؛ لا تُغيَّر أعلام `IsLocked`.

## تبادل العملي

لم تُعدّل هذه المهمة ملفات `ScheduleGenerator.cs` أو `ScheduleGenerationState.cs` أو `ScheduleService.cs` أو قواعد العملي الأصلية. المحرر مستقل عن مسارات التوليد العام وExcel، ويعيد استخدام أدوات التحقق واختيار القاعات القائمة.

في الشعبة والفصل المتأثرين بالعملي المقسّم لمجموعتين، يفرض النموذج تبادل المادتين بين المجموعتين في اليوم نفسه بفترتين متتاليتين بحسب ترتيب الفترات الحالي، مع ثبات تدريسي كل مادة ومختبرها بين حصتيها، وعدم أي تعارض. تُسمح مادة منفردة متبقية عندما يكون عدد وحدات العملي فرديًا، وفق الاستثناء السابق. العملي للشعبة كاملة في المرحلة الرابعة يبقى للشعبة كاملة ولا يدخل تبادل مجموعتين.

إذا كان نقل العملي يستلزم تحريك محاضرات تدريسي آخر أو كسر التبادل، يُرفض المقترح بدل تجاوز القاعدة. البيانات الناقصة للمجموعات تُرفض برسالة واضحة. تكرارات المادة تُقرن حسب ترتيب الحصص المحفوظة لكل مجموعة؛ لا تُدمج ولا تُسقط.

هذه الإضافة لا تصلح أو تغير الإعداد المرن السابق `RequirePracticalExchange=false` في التوليد العام أو استكمال Excel. الالتزام الإلزامي الموصوف هنا يخص محرر أيام التدريسي الجديد؛ لم يُعدّل سلوك المسارات القديمة أثناء هذه المهمة بناءً على طلب الحفاظ على خوارزمياتها.

## البحث والتحسين

استخدمت مكتبة `Google.OrTools` بإصدار مثبت `9.15.6755`، ضمن BLL. لكل محاضرة اختيار واحد بالضبط من تركيبات اليوم والفترة والقاعة الصالحة. إشغال الآخرين يُستبعد، وإشغال التدريسي يُقيد بعدم التزامن. علاقات التبادل قيود إلزامية، وليست عقوبات يمكن تجاهلها.

يبحث النمطان أولًا داخل الأيام المختارة فقط. في النمط الصارم لا يُبحث خارجها. في نمط التفضيل لا يبدأ البحث في الأيام الأخرى المسموحة إلا إذا أثبت البحث الأول عدم وجود حل داخل المختارة. انتهاء المهلة دون نتيجة لا يُعرض بوصفه استحالة مثبتة.

ترتيب التحسين داخل الحلول الصالحة، بأوزان تضمن أولوية كل مستوى على جميع المستويات التالية:

1. أقل عدد من المحاضرات خارج الأيام المفضلة عند السماح بذلك.
2. أقل عدد من المحاضرات المتغيرة.
3. أقل تغييرات الأيام والفترات.
4. أقل تغييرات القاعات.
5. أفضل توافق مع الفترات المفضلة.
6. أقل فراغات بين محاضرات التدريسي في اليوم الواحد.

تظهر حالة CP-SAT كما هي: `Optimal` أو `Feasible` أو `Infeasible` أو `Unknown`. الحل الصالح غير المثبت مثاليًا قابل للمعاينة؛ لا يُحفظ تلقائيًا. المهلة الافتراضية 20 ثانية ويمكن تعديلها حتى 120 ثانية. الإلغاء مدعوم.

## الحفظ

تُلتقط بصمة للجداول الأكاديمية التسعة عند المعاينة. عند الحفظ تبدأ معاملة `Serializable`، وتُرفض العملية إذا تغيّر أي مورد أو حصة منذ المعاينة. يعاد فحص الهوية والمدة والأيام والتعارضات والتبادل.

تعالج DAL تبديل الفترات الدائري مع الفهارس الفريدة في SQL Server بإزالة السجلات المتغيرة فقط وإدراجها بالمعرّفات نفسها داخل المعاملة، مع `IDENTITY_INSERT` عند الحاجة. لا تُمس سجلات المحاضرات غير المتغيرة. تُقارن النتيجة الكاملة بالمقترح قبل الالتزام. فشل أي خطوة يعيد العملية كاملة؛ الاختبارات تشمل فشلًا بعد الإزالة وقبل إعادة الإدراج. لا يتغير مخطط القاعدة أو إعداد الاتصال بها.

## إزالة Locked

أُزيل عمود **Locked** وقائمة القفل/إلغاء القفل من شاشة جدول المحاضرات. بقي الحقل الداخلي والمخطط وتوافق استيراد Excel كما هي لتجنب كسر الوظائف القائمة. لا يستخدم المحرر الجديد أقفالًا دائمة لحماية محاضرات الآخرين.

## التحقق والحدود

- نجح Build لكل مشاريع Solution في Debug وRelease: صفر أخطاء وصفر تحذيرات.

- اختبارات المحرر الجديدة: 22 مجموعة، تشمل المنطق والمعاملات والحفظ والإلغاء والمعاينة العربية على حجمي 800×600 و1180×820.
- اختبارات العملي السابقة: 21 ناجحة دون تعديل ملفاتها.
- اختبارات الاستيراد: 23 ناجحة دون تعديل ملفاتها.
- نسخة معزولة من الجدول الفعلي: حفظ نقل محاضرة واحدة لتدريسي مع بقاء 277 محاضرة وجميع هوياتها ومحاضرات الآخرين دون تغيير. ثلاث تجارب للعملي على النسخة رُفضت بسبب القيود الحالية؛ لم تُكسر القواعد لتوفير اقتراح.
- الجداول التسعة في القاعدة الفعلية قورنت قبل وبعد العمل وبقيت مطابقة؛ العدد 277، والأقفال صفر. لم يُنفذ حفظ أو توليد على القاعدة الفعلية.
- الصور والنتائج: `output/faculty-editor-verification/`. أدلة مراجعة النسخة الفعلية: `.tmp/FacultyEditor20261019/`.
- واجهة المحرر لسطح المكتب؛ لم تُضف واجهة ويب مقابلة. التفضيلات تخص العملية الحالية ولا تُخزَّن كسياسة دائمة.
- فحص DPI الفيزيائي عبر إعدادات Windows متعددة غير منفذ؛ النافذة تستخدم `AutoScaleMode.Dpi` وتخطيطًا متجاوبًا.
- النموذج الفعلي يسند المحاضرة إلى تدريسي واحد. لم تُضف علاقة تدريس مشترك أو مفهوم محاضرة متعددة الفترات غير موجود في البيانات.
- إذا كان الجدول الحالي لا يحقق قيود العملي ولم يكن إصلاحه ممكنًا دون تحريك الآخرين، يرفض المحرر المقترح. عدم وجود حل في هذه الحالة لا يبرر تغيير محاضرات الآخرين.

لتشغيل التحقق:

```powershell
dotnet run --project tests/FacultyScheduleEditor/FacultyScheduleEditor.csproj -c Release -- ui
```

تنشئ الاختبارات قاعدة SQL Server مستقلة باسم يبدأ بـ`UniversityTimetable_FacultyEditor_`. لا تستخدم قاعدة المستخدم. تحتاج مكتبة OR-Tools الأصلية إلى تشغيل Windows بنواة x64 في بيئة التطبيق الحالية.
