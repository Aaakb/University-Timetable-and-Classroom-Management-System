# تقرير تحديث الاسم الرسمي

الاسم المعتمد: **University Timetable Management System**.

أُعيدت تسمية ملف الحل إلى `University Timetable Management System.slnx`.
بقيت أسماء المشاريع الداخلية وNamespaces وAssembly Names ومسارات المشاريع
كما هي، بما فيها `Presentation_Layer` و`UniversityTimetable.API`، لحماية المراجع.
الاسم الطويل المتبقي داخل مسارات الملفات هو اسم مجلد فعلي مقصود، وليس اسمًا رسميًا ظاهرًا للمستخدم.

## التحقق

- نجح بناء **Debug** لجميع المشاريع الخمسة: **0 أخطاء و0 تحذيرات**.
- نجح بناء **Release** في مجلد مستقل: **0 أخطاء و0 تحذيرات**.
- نجح تشغيل الملف التنفيذي لنسختي Debug وRelease والوصول إلى شاشة الدخول بالاسم الجديد. استخدم فحص التشغيل قاعدة بيانات اختبار معزولة؛ لم يُشغّل التحديث على قاعدة بيانات المستخدم.
- فُحصت نوافذ الدخول وإنشاء الحساب والنافذة الرئيسية، وصُوّرت للتأكد من وضوح الاسم. بقي زر إدارة القاعات موجودًا.
- اشتغل API على منفذ اختبار محلي، ونجح فحص CSRF واستمرار رفض الوصول غير المصرح به إلى بيانات القاعات.
- نجح فحص الويب في Edge فعلي يعمل دون واجهة مرئية: عنوان المتصفح، العلامة، ملف PWA، أحجام 390 و768 و1366 بكسل، وصفحة عدم الاتصال بعد تفعيل Service Worker، دون أخطاء JavaScript.
- قورنت بصمات **65 ملفًا** قبل التعديل وبعده في BLL وDAL والنماذج ومصادر API وإعدادات الاتصال والتشغيل: **لم يتغير أي منها**. استُثني ملف مشروع API من المقارنة لأنه يتضمن بيانات المنتج المعدلة.
- تبقى قاعدة البيانات `UniversityTimetable` وسلسلة الاتصال الحالية كما هما. لم تتغير الجداول أو العلاقات أو خوارزميات الجدولة أو وظائف إدارة القاعات.

أدلة فحص التشغيل والصور محفوظة محليًا في `.tmp/ProjectRename/`.

## مشكلة ملفات Release المفتوحة

كانت هناك نسخة Release مفتوحة من التطبيق تقفل بعض ملفات المجلد المعتاد،
فتعذر إتمام نسخ مخرجات البناء إليه. لم تُغلق تلك النسخة أو جلسة المستخدم.
عولجت المشكلة ببناء Release في مجلد مستقل باستخدام:

```powershell
dotnet build "University Timetable Management System.slnx" -c Release --artifacts-path output/renamed-release
```

الملف التنفيذي الجديد:

```text
output/renamed-release/bin/Presentation_Layer/release/Presentation_Layer.exe
```

النسخة المفتوحة سابقًا تعرض الاسم الذي حُمّل عند تشغيلها؛ يظهر الاسم الجديد عند
تشغيل النسخة الجديدة. لتحديث مجلد Release المعتاد لاحقًا، أغلق النسخة القديمة ثم
أعد البناء بالطريقة المعتادة. قد تعرض نسخة PWA المثبتة إشعار تحديث التطبيق الموجود أصلًا؛
تحديثها يحمّل مخزن الملفات الثابتة الجديد دون تغيير هوية التطبيق المثبت أو حسابات المستخدمين.
