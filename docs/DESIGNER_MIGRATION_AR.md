# تحويل النوافذ المبنية بالكود إلى Windows Forms Designer

آخر مراجعة: 25 أكتوبر 2026.

أصبحت النوافذ الأربع التالية مقسّمة إلى ملف للسلوك وملف `Designer.cs` لعناصر الواجهة وخصائصها:

| النافذة | الملف الرئيسي |
| --- | --- |
| استيراد Excel وPDF | `ExcelImportForm.cs` |
| تفضيلات أيام التدريسيين | `FacultyPreferencesForm.cs` |
| تغيير أيام التدريسي | `FacultyScheduleEditorForm.cs` |
| الجداول البديلة | `TimetableAlternativesForm.cs` |

سُجّلت النوافذ في المشروع بنوع `Form` وربطت ملفات المصمم بالملفات الرئيسية. أُضيف مورد تفضيلات الأيام، وأُدرج مورد محرر الأيام الموجود مسبقًا. تظهر بطاقات الأيام الخمس في مصمم التفضيلات، بينما تُربط قيمها الفعلية بعد تحميل القوائم وقت التشغيل.

نُقلت أيضًا أزرار الاستيراد وتفضيلات التدريسيين والجداول البديلة إلى ملف تصميم النافذة الرئيسية `MainShellForm.Designer.cs`؛ بقيت أحداث فتح النوافذ وتحديث الصفحة بعد الحفظ في ملف السلوك.

لم تُعدّل واجهة تسجيل الدخول خلال هذا العمل، لأنها تدعم المصمم مسبقًا. لم تتغير خدمات الأعمال أو ملفات الوصول إلى البيانات خلال هذا التحويل، ولم تُنفّذ عمليات استيراد أو حفظ أو توليد على قاعدة البرنامج. التعديلات الموجودة في هذه الطبقات عند بدء العمل بقيت كما كانت.

## الحفاظ على الواجهة والسلوك

حُفظت نسخة المصادر السابقة في `.tmp/DesignerMigration20261024/before` ونسخة البرنامج السابقة في `original-app` داخل المجلد نفسه. تشمل المقارنة مواضع العناصر وأبعادها وألوانها وخطوطها ونصوصها والأعمدة والقوائم والأحداث في وضعَي التشغيل والتصميم.

حُدد ارتفاع أدنى لثماني حاويات حقول للحفاظ على أبعادها السابقة بعد التسلسل إلى ملف المصمم: ثلاث بارتفاع 38 في الاستيراد، وثلاث بارتفاع 34 في محرر الأيام، واثنتان بارتفاع 58 في التفضيلات. هذه مقاسات يدعمها تحجيم DPI المعتاد. حُفظ ترتيب تهيئة أعمدة مقارنة البدائل لأن ترتيب ضبط عرض الأعمدة يؤثر في توزيعها التلقائي.

وضع التصميم لا ينشئ خدمات قاعدة البيانات ولا يربط أحداث التحميل أو الحفظ. يحتفظ حقل نوع البيانات في مصمم الاستيراد بالمفتاح `StudyYears`؛ يُعرض النص العربي بواسطة حدث التنسيق وقت التشغيل، مع بقاء القيم المخزنة كما هي.

## نتائج التحقق

| الفحص | النتيجة |
| --- | --- |
| بناء Release | صفر أخطاء وصفر تحذيرات |
| بناء Debug | صفر أخطاء وصفر تحذيرات |
| مقارنة الواجهات الأربع، وأحداثها، وأنماط الاستيراد، وبطاقات الأيام وأزرار النافذة الرئيسية | 124 ناجحًا، صفر فشل |
| الواجهات العربية الأساسية | 54 ناجحًا، صفر فشل |
| دورة حياة عناصر عناوين Guna في المصمم | 80 ناجحًا، صفر فشل |

تعليمات الاختبار وحدوده في [اختبار التحويل](../tests/DesignerMigration/README.md). حُفظت نسخة قابلة للتسليم من [سجل التحويل](Verification/DesignerMigration/designer-migration.log)، و[نتائج الفحوص](Verification/DesignerMigration/checks.json)، وسجلات البناء والعربية ودورة حياة العناصر في `docs/Verification/DesignerMigration`. النتائج المحلية التفصيلية واللقطات في `.tmp/DesignerMigration20261024/final`، وسجلات التشخيص في المجلد الأب. هذه الملفات المحلية مهملة من Git؛ لا تُعد نسخًا احتياطية لقاعدة البيانات.

فحوص البناء وإنشاء العناصر والرسم والمقارنة لا تُثبت وحدها إتمام دورة فتح المصمم وتعديل خاصية وحفظها وإغلاقها وإعادة فتحها داخل Visual Studio. لم تكتمل هذه الدورة حتى هذه المراجعة؛ تعذر استهداف نافذة فتح الملف التابعة لـ Visual Studio بأداة التحكم. لذلك لا يُدّعى اجتياز هذا الفحص اليدوي.

## فتح واجهة للتعديل

افتح الحل في Visual Studio، ثم من مشروع `Presentation_Layer` افتح مجلد `PresentationLayer`. اختر الملف الرئيسي المطلوب، مثل `ExcelImportForm.cs`، واضغط `Shift+F7` أو اختر **View Designer** من قائمته. يُستخدم الملف الرئيسي لفتح المصمم، وتُحفظ خصائص العناصر تلقائيًا في ملف `Designer.cs` التابع له.
