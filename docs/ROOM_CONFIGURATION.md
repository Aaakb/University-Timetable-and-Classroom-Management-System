## شرط التبادل

التبادل المتتالي بين مجموعتي العملي مفضّل وليس إلزامياً، وفق اختيار المستخدم. إذا لم يتوفر تبادل كامل تُوزّع حصتا المجموعتين على فترات متاحة، ويمكن إصلاح توزيع العملي لاستيعاب النظري. يبقى منع تعارض المكان والمدرس والشعبة/المجموعة، ومراعاة السعة وتكليف التدريس، إلزامياً. يحفظ النظام الجدول السابق إذا تعذر توليد جميع الحصص المطلوبة.

سبب تعديل الشرط: البيانات الكاملة تحتاج 16 كتلة تبادل في الكورس الأول و17 في الثاني. مع ثلاث فترات يومية، كل كتلة متتالية تشغل الفترة الوسطى في مختبرين؛ سبعة مختبرات تستوعب ثلاث كتل يومياً فقط، أي 15 أسبوعياً.

## التحقق بالبيانات الكاملة

استُنسخت قاعدة المشروع الأصلية كاملة باستخدام SQL Server backup/restore: 92 مادة، 18 مدرساً، 276 تكليفاً، 10 شعب و269 حصة. لم يُقلص عدد المواد أو الشعب للتجربة.

نجح التوليد وإعادة التوليد على النسخة الكاملة: 269/269 حصة، دون حصص متروكة، باستخدام 11 مكاناً والفترات الثلاث نفسها. قورنت حصص كل مادة/شعبة/كورس/نوع/مجموعة بالجدول السابق، وفُحصت السعات وأنواع الأماكن والتعارضات الزمنية بين القاعات والمدرسين والشعب والمجموعات.

اختبارات الانحدار: 27 فحصاً للجدول والخدمات، منها إعداد 4+7، حفظ نوع المختبر المشترك عبر إعادة التشغيل، الحجز النظري والعملي، رفض حجز المختبر المشترك مرتين، والحفاظ على الجدول عند نقص السعة. اختبارات التبادل الصارم تحتفظ بتغطيتها الداخلية، بينما اختبارات الخدمة تتحقق من الوضع المرن المستخدم في التطبيق.

ملفات التجربة والنسخة الاحتياطية والنتيجة المفصلة محفوظة تحت `.tmp/RoomConfiguration`؛ ملف `backup.txt` يحتوي مسار نسخة SQL Server الاحتياطية، و`verified.json` يحتوي نتيجة الفحص والتوزيع. أداة التطبيق تتحقق من عدم تغيير بيانات الأصل منذ التجربة، وتطبّق التوزيع داخل معاملة واحدة مع المحافظة على معرفات الحصص وجميع جداول المواد والمدرسين والتكليفات والشعب والأوقات.
