# جداول بديلة للجدول المحفوظ

## لماذا كان يظهر الجدول المستورد نفسه؟

زر **توليد جدول جديد** يعيد الآن بناء محاضرات الفصلين من المواد والتكليفات الحالية، ويحتفظ بالمحاضرات التي يثبتها المستخدم فقط، مع حفظ نسخة من الجدول السابق تلقائياً قبل الاستبدال. تنويع المحاولات لا يضمن اختلافاً عندما تفرض القيود توزيعاً واحداً. يظل مسار الإكمال الداخلي متاحاً للاستخدامات التي تحتاج حفظ المحاضرات السابقة.

أُضيف مسار مستقل باسم **جداول بديلة** في قائمة سطح المكتب، وفي قائمة الويب عند `/alternatives.html`. يستعمل المحرك القائم نفسه، ولا يستبدل الجدول أثناء الاستكشاف.

## الاستخدام

1. افتح **جداول بديلة** واختر الفصل والمهلة، حتى 120 ثانية.
2. راجع الجدول الحالي وعدد المحاضرات المثبتة. إذا كانت كلها مثبتة فلن يغيرها البحث. من تبويب **الجدول الحالي والأقفال** حدد المحاضرات التي تسمح بتحريكها، ثم اختر **إلغاء تثبيت المحاضرات المحددة** وراجع التأكيد. يمكن استخدام Ctrl+A لتحديد الكل. فك التثبيت يحفظ بيانات الأقفال فقط، دون تغيير المواعيد، وهو إجراء صريح مستقل عن البحث.
3. اضغط **إنشاء حتى 3 بدائل**. يبقى الجدول الحالي أول صف للمقارنة.
4. قارن البدائل بحسب عقوبة التفضيل، وفراغات التدريسيين والطلبة، وأعلى عبء يومي، وعدد المحاضرات المتغيرة والتدريسيين المتأثرين.
5. اختر صف البديل لعرض محاضراته وتوزيعه الأسبوعي. يمكن تصفية المعاينة حسب التدريسي؛ هذه تصفية للعرض فقط، والبديل يشمل الفصل كله. تظهر المجموعة ونوع المحاضرة والمرحلة والفرع ضمن التفاصيل.
6. اضغط **اعتماد البديل المحدد** بعد المراجعة. اختيار صف الجدول الحالي يعطل الاعتماد.

إذا لم تتوفر ثلاثة بدائل، يعرض النظام ما وجده فقط. لا يُكرر الجدول نفسه بأسماء مختلفة، ولا يعد تبديل القاعة وحده بديلاً زمنياً جديداً. قد يكون الجدول الحالي مساوياً للبدائل أو أفضل في بعض المقاييس؛ العناوين تصف هدف البحث، ولا تعني أن كل بديل أفضل من الحالي في جميع الجوانب.

## البحث والحماية

- يُعاد استخدام `ImportedTimetableRepairPlanner` وCP-SAT، مع خيارات خاصة بالبدائل لا تغير سلوك إصلاح الملف القديم.
- المتغيرات هي اليوم والفترة والقاعة فقط. لا تتغير هويات المحاضرات أو المادة أو التدريسي أو الشعبة أو المجموعة أو المدة.
- تُفرض جميع التعارضات وقواعد القاعات والعملي، وتبقى المحاضرات المثبتة ثابتة.
- تبقى أيام الحضور المحفوظة للتدريسي يومين أو ثلاثة، وتبقى الفترات المرفوضة ممنوعة. من لم تُدخل له تفضيلات يظل خاضعاً لقواعد الجدولة القائمة دون افتراض ملف تفضيلات جديد له.
- يستبعد كل بحث الجدول الحالي والبدائل السابقة في المجموعة بشرط اختلاف موعد محاضرة واحدة على الأقل، مع السماح بتبديلات مترابطة.
- تُحسّن عقوبة التفضيلات أولاً وعدالة التعادل، ثم الهدف الخاص: أقل تغييرات، أو أقل فراغات للتدريسيين، أو أقل عبء يومي أقصى للطلبة. تُستخدم مقاييس فعلية للمقارنة، وليس درجة جودة اعتباطية.
- إذا كان الجدول الحالي يحقق إتاحة وتفضيلات الحضور، تُقيّد البدائل بعدم زيادة مجموع عقوبات التفضيل الحالي. إذا كان يخالفها، يبحث النظام عن بديل يحققها دون استخدام العقوبة وحدها لتبرير مخالفة.
- البحث محدود بالوقت وحجم الخيارات، ولا يضمن ثلاثة بدائل ولا نتيجة مختلفة عند تكرار البحث بالمدخلات نفسها. النتيجة قابلة لإعادة الإنتاج؛ التنوع داخل المجموعة محقق بقيود اختلاف صريحة.
- إثبات `Optimal` يخص النموذج والهدف مع استبعاد الجداول السابقة، وليس ادعاء أمثلية مطلقة تشمل كل جدول ممكن. `Unknown` لا يثبت عدم وجود بدائل.
- تُفحص الخطة الكاملة قبل عرضها للحفظ، وتُفحص ثانية داخل معاملة Serializable عند الاعتماد. أي تغير في البيانات أو التفضيلات أو الأقفال يبطل الموافقة القديمة. تُحفظ التغييرات بالكاتب الذري القائم وبالمعرفات نفسها.
- معاينة الويب محفوظة في ذاكرة الخادم ومقيدة بالحساب، مع حماية الجلسة وCSRF. لا يقبل الاعتماد خطة يرسلها العميل؛ يقبل معرّف معاينة لم تنته صلاحيتها فقط.

## الملفات والتحقق

المكونات الجديدة: `TimetableAlternativeModels.cs` و`TimetableAlternativesService.cs` في BLL، و`TimetableAlternativesForm.cs` في العرض، و`TimetableAlternativesController.cs` وصفحة `alternatives.html` ووحدة `alternatives.js` في الويب. تغيرت نقاط الربط في القائمة والتسمية، وامتد المحرك المشترك بخيارات اختيارية للبدائل.

```powershell
dotnet build "University Timetable and Classroom Management System.slnx"
dotnet run --project tests/FacultyPreferences/FacultyPreferences.csproj -- ui web alternatives-ui
dotnet run --project tests/ImportedTimetableRepair/ImportedTimetableRepair.csproj
dotnet run --project tests/IncrementalGeneration/IncrementalGeneration.csproj
```

الاختبارات تستخدم قواعد معزولة: 32 مجموعة تحقق في تفضيلات التدريسيين والبدائل، و19 في إصلاح المستورد، و8 في التوليد التدريجي. تغطي تميز البدائل زمنياً، وثبات الأيام، وعدم تراجع التفضيلات، وعدم الكتابة أثناء البحث، والحفظ المختار، والأقفال والفك الصريح، والمعاينات القديمة، وحالة وجود توزيع واحد فقط، والإلغاء، ودورة الويب، والواجهة عند 900 و1180 بكسل.

الصور ونتائج الاختبارات والمقارنة في `output/faculty-preferences-verification/`، بما فيها `alternatives-900.png` و`alternatives-1180.png` و`timetable-alternatives.json`. جرى فحص واجهة سطح المكتب بصرياً؛ تحقق الويب آلياً على مستوى HTTP وتركيب JavaScript، وليس اختباراً بصرياً شاملاً للمتصفح.
