# إصلاح تشغيل SQLEXPRESS — 15 أكتوبر 2026

كانت الخدمة `MSSQL$SQLEXPRESS` تعمل وقت الفحص، ومضبوطة على Automatic (Delayed Start)، دون أي إجراءات استعادة بعد الفشل. سجل Windows أظهر عدة توقفات غير متوقعة (7034) وانهيارات `sqlservr.exe` (1000) خلال الأيام السابقة، بما فيها رموز `0xc0000005` و`0xc0000006` في ntdll.dll/CLR. لذلك المشكلة ليست إعداد Manual فقط. لم يثبت الفحص سبب الانهيار الجذري.

طُبقت الإعدادات بصلاحيات مسؤول بعد موافقة Windows:

- التشغيل: Automatic، دون التأخير السابق.
- عند الفشل الأول والثاني واللاحق: إعادة تشغيل الخدمة بعد 60 ثانية.
- إعادة ضبط عداد الإخفاقات بعد يوم دون إخفاق.
- تفعيل الاستعادة بعد التوقف بخطأ أيضاً.

لم تُوقف الخدمة العاملة أو يُعد تشغيل الحاسوب لإجراء هذا التعديل. جرى التحقق من `sc.exe qc` و`qfailure` و`qfailureflag`، ومن اتصال قاعدة `UniversityTimetable` ووجود المواد الـ96. الخدمة بقيت Running.

تأكيد التشغيل الفعلي مع إقلاع Windows ينتظر إعادة التشغيل التالية. الإعداد يعالج التشغيل والاستعادة التلقائية، ولا يثبت إصلاح سبب انهيارات SQL Server السابقة. لم يجد الفحص القرائي للأيام السبعة السابقة أحداث قرص/NTFS/WHEA ذات صلة في سجل النظام، لكنه لا يستبعد أسباباً أخرى.

السكربت وسجل تنفيذه ونسخة الإعداد السابق: `.tmp/SqlExpressFix/Configure-SqlExpress.ps1` و`configuration.log` و`result.json` و`startup-before.txt` و`recovery-before.txt`.
